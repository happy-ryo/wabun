# 主張の監査: 断定と根拠のつり合いを点検する

## このスキルの性格

文体は見ない(それは /wabun:suiko の仕事)。見るのは**主張と根拠のつり合い**。
出力は指摘の一覧であり、本文の書き換えはユーザーが指示するまで行わない。

このスキルは機械的な検出器を持たない。誤りの型と点検の手順を言語化した
ものであり、判定は文脈を読んで行う。型は実際の失敗事例から抽出した。

## 誤りの4型

いずれも「一文だけ読むと自然で、根拠と突き合わせて初めて崩れる」型である。
文法チェックでは見つからない。

### 型1: 範疇錯誤 — X の正体は Y

「この非対称の均衡が翻訳調の正体」— 均衡は翻訳調が*残り続ける理由*であり、
翻訳調*そのもの*ではない。定義・原因・結果・存続条件は別の種類のもので、
「正体」「本質」「にほかならない」で結ぶときに混ざりやすい。

点検: 「X は Y である」の X と Y は同じ種類か。Y は X の定義か、原因か、
結果か、それが続く理由か。種類が違うなら文を分けて関係を明示する。

### 型2: 過大一般化 — 測った範囲を超える「全て」

「名詞化の密度も全条件で変わりませんでした」— 実際に測ったのは 4 条件の
うち 2 条件だけだった。「全て」「常に」「どの〜も」「必ず」は、根拠が実際
にカバーした範囲を超えて滑りやすい。

点検: 全称表現ごとに「根拠はこの範囲を本当に覆っているか」を確認する。
覆っていなければ「測定した範囲(AとB)では」のように範囲を明記する。

### 型3: 交絡の脱落 — 自分で認めた限界を落とした断定

「ジャンルだけで 15→41 まで上がります」— 検証の過程では「C にも翻訳文体
が混入しうるので寄与は分離できない」と認めていたのに、まとめでは「だけで」
と断定した。要約・清書の段階で、認めていたはずの限界が脱落する。

点検: 「〜だけで」「〜が原因で」という単因の断定に対し、検証過程や本文の
他所に別の説明・既知の交絡が書かれていないか探す。あれば注記として戻す。

### 型4: 主語の不在 — 誰の変化かを言わない過程表現

「語彙だけ直してもまた戻ります」— 一度直した文書は戻らない。戻るのは
書き手の習慣・次に書く文書の側で、それを言わないと読者は文書が劣化する
かのように読む。変化・傾向を述べる文で主体を省くと起きる。

点検: 「戻る」「増える」「壊れる」など変化を述べる文の主体は明示されて
いるか。文書か、書き手か、プロセスか、集団の傾向か。

### 付録: 型0 — 事実の転記ずれ

「同一の題材について条件だけ変えて」— 実際は 1 条件だけ題材が違った。
論理ではなく事実の誤りだが、要約を重ねるうちに細部が滑らかな嘘に均される
点で同根。手続き・数値・固有名詞の記述は一次記録と突き合わせる。

## 手順

### 1. 候補の当たり付け(機械)

対象ファイルから断定・単因・全称の候補文を挙げる。網羅ではなく見落とし
防止の補助である。

```bash
grep -nE '(すべて|全て|全条件|常に|必ず|一切|あらゆる|どの.{1,6}も|だけで|のみで|が原因|正体|本質|にほかならない|同一の|完全に)' 対象ファイル
```

### 2. 主張の抽出(判定)

候補に限らず本文を通読し、検証可能な主張(事実・数値・因果・一般化)を
文単位で拾う。感想・意図の表明は対象外。

### 3. 突き合わせ

主張ごとに 4 型 + 型0 の点検質問を当てる。根拠は次の順で探す:
本文内の他所 → 同じリポジトリの一次記録(データ、実験ログ、テスト) →
会話履歴。根拠が確認できない主張は「未確認」として型と別に列挙する。

### 4. 報告

次の形式の一覧で報告する。書き換えはしない。

| # | 該当文(抜粋) | 型 | 何が問題か | 修正案 |
|---|---|---|---|---|

- 問題なしの場合はその旨を短く報告して終わる。指摘ゼロを恐れて
  微細な言い換えを並べない。
- 修正はユーザーが選んだ項目のみ適用する。適用時は主張の強さを
  根拠の強さに合わせる(弱める方向が基本だが、根拠が強いのに
  弱く書いている場合は強める方向も正しい)。

## 限界

- 判定は文脈理解に依存する。根拠(一次記録)にアクセスできないと
  型2・型3・型0 の検出力は大きく落ちる。
- 「〜と考えている」「〜の可能性がある」と留保された主張は、留保が
  適切ならば指摘しない。留保を外させることが目的ではない。
